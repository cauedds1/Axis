#5 - Super Admin Panel — AXIS
What & Why
Build a complete, production-grade Super Admin Panel accessible only to the user whose email matches the ADMIN_EMAIL environment variable. The panel must follow the AXIS visual design system (dark theme, same typography, colors, and component patterns as the rest of the app) and give the administrator full visibility and control over every dimension of the system — users, revenue, organizations, AI usage, WhatsApp, email alerts, and system health. The admin should never need to access the database directly.

Done looks like
Accessing /admin redirects to a password-protected area (existing isAdminUser check via ADMIN_EMAIL)
A sidebar with 9 sections navigates between panels without page reload
Every panel loads real data from new /api/admin/* endpoints
All tables support search, sort, and pagination
All charts are interactive (hover tooltips, period toggles)
Actions (deactivate user, impersonate org, send test email) give real-time feedback
The panel is fully responsive and matches AXIS dark aesthetic
No placeholder data — everything wired to the real DB and Stripe API
Out of scope
Multi-admin roles (single admin via ADMIN_EMAIL is enough)
CSV export (future)
Editing user financial data directly
Real-time websocket push (polling is fine)
Steps
1. Backend — Admin middleware and shared utilities
Create a reusable requireAdmin Express middleware that checks isAdminUser and returns 403 if not admin. All /api/admin/* routes use this middleware. Create a helper getPaginationParams(req) for consistent page/limit/search query handling.

2. Backend — Dashboard Geral endpoints
Create GET /api/admin/stats returning:

Total users (all, personal, business, collaborator)
Active users last 7 days and last 30 days (based on most recent transaction, habit, or task created)
Total transactions in the system
Total organizations
New signups per day for the last 30 days (for growth chart)
Users by account type breakdown
Top 5 most active users
3. Backend — User management endpoints
Create:

GET /api/admin/users — paginated list with search by name/email, filter by plan/accountType, sort by createdAt/lastActivity. Returns: id, name, email, plan, accountType, createdAt, stripeSubscriptionId, trialEndsAt, transactionCount, habitCount, taskCount, disciplineScore
GET /api/admin/users/:id — full user profile with all counters and recent activity
POST /api/admin/users/:id/deactivate — soft-delete or flag the account
POST /api/admin/users/:id/reset-password — send password reset email via SendGrid
DELETE /api/admin/users/:id — hard delete with cascade (all user data)
PATCH /api/admin/users/:id/plan — manually override a user's plan (for manual trials, support, etc.)
4. Backend — Organization management endpoints
Create:

GET /api/admin/organizations — paginated list with total members, total expenses, owner email, status
GET /api/admin/organizations/:id — full org profile: members list, expense breakdown, approval stats
POST /api/admin/organizations/:id/impersonate — sets a session flag that routes the admin into the org's business context for debugging (read-only access)
5. Backend — Financial monitoring endpoints
Create:

GET /api/admin/finance/overview — total transaction volume per month (last 12 months), top 10 categories globally, average spend per user, currency distribution
GET /api/admin/finance/transactions — paginated global transaction list with user, amount, category, date, type filters
6. Backend — Billing / Stripe endpoints
Create:

GET /api/admin/billing/overview — reads from users table: count by plan (starter/personal_ai/team), active trials with expiry dates, MRR estimate ($9 × personal_ai count + $29 × team count), subscriptions created in last 30 days
GET /api/admin/billing/subscriptions — list all users with active stripeSubscriptionId: userId, email, plan, stripeCustomerId, stripeSubscriptionId, trialEndsAt, created
7. Backend — WhatsApp Manager endpoints
Reuse existing endpoints (/api/whatsapp/status, /api/whatsapp/connect, /api/whatsapp/disconnect, /api/whatsapp/reset) — already admin-guarded. Add:

GET /api/admin/whatsapp/logs — last 100 messages processed by the WhatsApp bot (user, input type, result, timestamp) — read from existing whatsappMessages or equivalent log table if it exists, otherwise pull from recent transactions/events that came via WhatsApp
8. Backend — Email alert log endpoints
Create:

GET /api/admin/email-logs — paginated history of all SendGrid emails sent: recipient, alert type (bill_alert / overdue_task / low_discipline / goal_deadline), sent_at, status (sent/failed). Read from an emailLogs table — create it with a migration if it doesn't exist, and add an insert into it inside the existing sendAlertEmail / alert sending functions.
9. Backend — AI usage monitoring endpoints
Create:

GET /api/admin/ai/overview — aggregate OpenAI call counts per type: audio_transcription, chat, receipt_analysis, pdf_analysis, onboarding_diagnosis. Read from a new aiUsageLogs table (or existing usageCounters if applicable). Create the table and instrument the key AI call sites (transcribeAudio, chatWithContext, processReceiptPhoto, processPDFExtract) to log each call with userId, type, tokensUsed (if available), and timestamp.
GET /api/admin/ai/status — whether OPENAI_API_KEY is set and valid (make a test ping to OpenAI models list endpoint)
10. Backend — System config endpoints
Create:

GET /api/admin/system/config — returns non-sensitive env var status: APP_URL, ADMIN_EMAIL (masked), OPENAI_API_KEY (set/not set), STRIPE_SECRET_KEY (set/not set), STRIPE_WEBHOOK_SECRET (set/not set), SENDGRID_API_KEY (set/not set), DATABASE_URL (set/not set, never expose value), SESSION_SECRET (set/not set)
GET /api/admin/system/health — DB connectivity check, uptime, Node version, memory usage
POST /api/admin/system/maintenance — toggle a MAINTENANCE_MODE flag in DB that the app reads to block non-admin requests with a 503 page
11. Frontend — Admin route guard and layout
Add /admin route to App.tsx. Create AdminLayout component: dark sidebar with AXIS branding, "Super Admin" label, 9 navigation items with icons (lucide-react), active state highlight, and a header bar showing the admin's email and a logout link. Gate the entire /admin/* tree with a query to /api/auth/is-admin — redirect to / if not admin.

12. Frontend — Dashboard Geral panel
Render stat cards for total users, active users (7d/30d), transactions, organizations. Show a line chart (recharts) for new signups over 30 days. Show a donut/pie chart for user type breakdown. Show a "Top Active Users" table. Use skeleton loaders while fetching.

13. Frontend — Gestão de Usuários panel
Searchable, paginated table of all users. Columns: avatar initial, name/email, plan badge (color-coded: Starter gray, Personal AI blue, Team purple), account type, signup date, transaction count, discipline score. Row actions (three-dot menu): View Profile, Override Plan, Reset Password, Deactivate, Delete (with confirmation dialog). Clicking a row opens a slide-over drawer with the full user profile (all stats, recent transactions, habits, tasks summary).

14. Frontend — Gestão de Organizações panel
Table of all organizations: name, owner email, member count, total expenses, status badge. Row actions: View Details, Impersonate. Details drawer shows member list with roles, expense breakdown by category, and pending approvals count.

15. Frontend — Monitoramento Financeiro panel
Line chart of total transaction volume per month (last 12 months). Bar chart of top 10 global categories. Stat cards: total volume, average per user, most used currency. Below: paginated global transactions table with user column, filterable by date range and category.

16. Frontend — Billing / Stripe panel
Stat cards: MRR (calculated), total paying users (personal_ai + team), users in trial, users on starter (free). Donut chart for plan distribution. Table of all subscribers: email, plan, trial end date, Stripe subscription ID (truncated), subscription start date. Each row links to the Stripe Dashboard for that customer (construct URL: https://dashboard.stripe.com/customers/${stripeCustomerId}).

17. Frontend — WhatsApp Manager panel
Connection status card with colored indicator (green connected, yellow QR pending, red disconnected). Show QR code image when in QR pending state (poll every 3 seconds). Buttons: Connect, Disconnect, Reset — each with confirmation. Below: log table of last 100 processed WhatsApp messages (user phone, message type, result summary, timestamp).

18. Frontend — Log de Alertas de Email panel
Paginated table of email logs: recipient, alert type badge, timestamp, status (sent ✓ / failed ✗). Filter by alert type. Stat cards: total sent, total failed, success rate.

19. Frontend — Controle de IA panel
Stat cards: total AI calls today / this month, calls by type (donut chart). Table of recent AI calls with user, type, timestamp. Status card: OpenAI key status (green valid / red missing). Prominently show a warning banner if OPENAI_API_KEY is missing or invalid.

20. Frontend — Configurações do Sistema panel
Grid of env var status cards (green = set, red = missing) for all critical variables. System health card: DB connected, uptime, memory. Maintenance mode toggle with confirmation. Each missing variable shows a hint for where to set it (Railway dashboard).
