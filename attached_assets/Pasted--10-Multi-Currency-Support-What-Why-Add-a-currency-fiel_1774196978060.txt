#10 - Multi-Currency Support
What & Why
Add a currency field to the user profile so the entire app — interface, AI, and WhatsApp bot — works in the user's chosen currency. Today everything is hardcoded to BRL (R$). After this change, a user who selects EUR will see € everywhere, and the bot will interpret "spent 50 on lunch" as €50.

Key design decisions:

No currency conversion — amounts are stored as-is in the user's chosen currency
Currency is set once during onboarding/settings and cannot be changed afterwards (locked)
The currency selector is shown in Settings but becomes read-only once saved
Supported currencies (19 total)
BRL R$ · USD $ · CAD C$ · MXN MX$ · ARS $ · COP $ · CLP $ · PEN S/ · UYU $ · EUR € · GBP £ · CHF Fr · JPY ¥ · CNY ¥ · INR ₹ · AUD A$ · SGD S$ · ZAR R · AED AED

Done looks like
A currency selector appears in Settings; once saved it becomes read-only with a lock icon
All monetary values in Finance, Dashboard, Business, Reports use the chosen currency symbol and locale formatting
The AI (chat + voice input) includes the user's currency in its context, so it correctly registers amounts
The WhatsApp bot registers amounts in the user's currency
Setup sheet (income/expenses) and onboarding show the correct currency symbol instead of hardcoded "R$"
If currency is not yet set, it defaults to BRL (backward compatible)
Out of scope
Currency conversion or exchange rates
Per-transaction currency override
Changing currency after it has been set
Tasks
Schema + backend — Add currency varchar field (default "BRL") to the userProfile table and run db:push. Define a SUPPORTED_CURRENCIES constant with all 19 currencies (code, symbol, locale, name). Expose currency in GET /api/user/profile and accept it in PATCH /api/settings only if currency is not already set (lock logic on the backend).

Settings UI — currency selector — Add a currency picker to the Settings page. If currency is not yet set, show a searchable dropdown. If it is already set, show it as read-only with a lock icon and tooltip explaining it cannot be changed. Save via the settings endpoint.

Frontend money formatter — Create a fmtMoney(value, currency) helper using Intl.NumberFormat. Replace all uses of the hardcoded fmtBRL function and R$ prefix across the frontend with this helper, reading the user's currency from the profile query. Files to cover: finance.tsx, dashboard.tsx, reports.tsx, all business pages, setup-sheet.tsx, bills-tab.tsx, credit-cards-tab.tsx, manage-bills-sheet.tsx, and PublicReport.tsx.

AI + bot currency awareness — Inject the user's currency (code, symbol, name) into the AI system prompts in server/ai.ts so the assistant correctly interprets and registers amounts in any language. Update the WhatsApp handler to forward the user's currency to the AI context. Update spending analysis and discipline scoring prompts to reference the user's currency symbol instead of hardcoded "R$".
